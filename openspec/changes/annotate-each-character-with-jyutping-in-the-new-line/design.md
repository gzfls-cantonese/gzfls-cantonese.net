# Design

## Context

数据流现状：`tools/pipeline/extract.py` 读取 parquet，为每条记录写出 `{id, duration, transcription, audio}` 到 `dist-assets/episodes/ep_*.json`；前端 `api.ts` 加载该 JSON，`ScriptPanel.tsx` 用 `@tanstack/react-virtual` 虚拟化渲染每行，仅显示 `transcription`（繁体）。数据集只有繁体文本，无粤拼。

约束（沿用项目既定架构）：纯静态分发、运行时零函数、控成本，因此粤拼 MUST 在构建期生成并随 JSON 分发，浏览器不做转换。繁体原样保留，不做简繁转换。

## Goals / Non-Goals

**Goals:**
- 构建期为每条记录生成与汉字逐字对齐、带声调数字的粤拼，写入 entry 新字段。
- 脚本面板在繁体下方渲染逐字对齐的粤拼行，支持换行后仍对齐，提供默认显示的开关。
- 字段缺失时优雅降级，不破坏现有繁体显示、播放、高亮、点击定位。

**Non-Goals:**
- 不做运行时（浏览器端）粤拼转换。
- 不改动音频、导航、封面、许可等其它能力。
- 不追求多音字在词组语境下的最优读音（见 Risks）。
- 不重做 `ScriptPanel` 的虚拟化机制。

## Decisions

### 决策 1：粤拼在构建期由 Python 库生成，逐字粒度
在 `extract.py` 中引入粤语 G2P 库（候选：PyPI `jyutping` 包或 `PyJyutping`），对 `transcription` **逐字**转换以保证与字符序列一一对应。
- 为什么逐字而非词组切分：需求要求「逐字对齐」，逐字转换天然产出与字符等长的序列，映射简单、对齐可靠。词组切分虽能改善多音字读音，但需再把词级结果映射回单字，复杂且易错位。
- 备选：浏览器端 JS 字典转换 —— 否决，违背「运行时零函数/控成本」，且增加包体积与运行时开销。

### 决策 2：数据契约用「与字符等长的字符串数组」
每条 entry 新增 `jyutping: string[]`，长度等于 `Array.from(transcription)` 的码点数，逐元素为该字粤拼（带声调，如 `sam1`），非汉字（标点/数字/空格）对应位置为 `""`。
- 为什么用数组而非空格拼接字符串：拼接串中的空格会与「非汉字留空占位」及粤拼内部空格冲突，前端无法可靠还原逐字对应。等长数组让前端 `zip(chars, jyutping)` 无歧义。
- 码点而非 UTF-16 length：用 `Array.from` 处理可能的代理对，保证与 Python 侧字符序列一致。

### 决策 3：前端用「每字一个竖排单元格」实现对齐
将每条脚本渲染为一串行内单元格，每个单元格是一个竖排 flex 列：上为汉字、下为对应粤拼；单元格随宽度自然换行。非汉字单元格的粤拼位留空占位（保持高度一致）。
- 为什么不用「两条独立文本行 + 等宽字体」：汉字字形宽度与粤拼音节宽度不等，独立两行无法逐字对齐，换行处更会错位。竖排单元格让每个视觉行天然形成「上汉字带、下粤拼带」，满足对齐与换行对齐要求。
- 虚拟化的 `estimateSize` 需上调（行高增加粤拼带），`measureElement` 已能自适应实测高度。

### 决策 4：开关状态放在 `ScriptPanel`（或 `EpisodePage`）本地 state
新增布尔 state，默认 `true`；关闭时不渲染粤拼单元格的下半部分。开关不触碰 `usePlayer`，故不影响播放与 `currentIndex`。

## Risks / Trade-offs

- **多音字读音可能不准** → 逐字转换在词组语境下可能选错读音。缓解：首期接受此权衡并在 About/文档标注「粤拼为自动生成的学习参考」；后续可在管线改用词组切分再映射回单字以提升准确率，数据契约（等长数组）保持不变。
- **生僻字/缺字无读音** → 字典未收录的字返回空。缓解：与标点一样留空占位，不中断，不报错。
- **全量资产需重跑管线** → JSON 体积增大（每字一个粤拼音节）。缓解：粤拼数组仅文本、增量有限；未重跑前旧 JSON 无该字段，前端按决策降级为不显示粤拼行。
- **逐字数组使 JSON 变长** → 每集约数百条、每条数十字，体积增长可控。缓解：CDN 传输 + gzip/br 压缩后影响小。
- **虚拟列表行高估算偏差** → 增加粤拼带后行更高。缓解：调大 `estimateSize` 并依赖 `measureElement` 实测。

## Migration Plan

1. 管线：`requirements.txt` 增加粤拼库依赖，`extract.py` 为每条 entry 生成并写入 `jyutping` 数组；先用 `--limit-episodes` 小样验证对齐与非汉字留空，再跑全量并过完整性校验。
2. 前端：扩展 `ScriptEntry` 类型、`ScriptPanel` 渲染与开关、`global.css` 竖排单元格样式；补充/更新单测覆盖「有字段渲染」「缺字段降级」「开关切换」。
3. 部署：重建 `dist-assets` 并按既有静态分发流程发布；粤拼字段向后兼容，旧前端读取新 JSON 不受影响。
4. 回滚：粤拼为纯新增字段与新增 UI，若需回滚，恢复旧 `ScriptPanel`/样式即可，JSON 中多余字段被旧代码忽略；必要时回退到未含该字段的上一版资产。

## Open Questions

- 最终选用哪个粤拼库（`jyutping` vs `PyJyutping`）及其对繁体、多音字的覆盖度，可在 apply 阶段以小样实测后定；不影响数据契约与前端设计。
